## 3. 已确认、不要静默更改的规则

### 3.1 评分与严选

- 已取消面向用户的种族分、旧个体百分分与 75%／25% 综合分。网站显示“物种梯级（S/A/B/C）＋个体梯级（S/A/B/C）＋同种白板产出倍率”；兼容字段 `finalScore` 必须与 `individualScore` 完全相等。
- 物种梯级以 `skills/pokemon-sleep-scoring/scripts/species-tiers.js` 为唯一可执行来源；未列入名单的最终形态默认 C，未进化个体继承所选最终形态。名单解释见 `docs/species-tier-draft.md`。
- 旧树果／食材／技能生产模型保留为队伍、岛屿和活动推演的内部诊断输入；不得再把它显示为“种族分”，也不得与个体质量合成百分分。
- 个体倍率按定位比较：食材手看目标食材产量，普通树果手看自然树果能量，技能手看期望触发次数，树果骤增看自然树果与技能树果总收益。白板为 1.00。
- 长期潜力计入五个已知副技能栏位；副技能种子只按游戏内合法升级，纯白薄荷只中和不利性格。页面同时披露当前倍率与潜力倍率。
- 普通树果位与树果骤增都要求树果数量 S；食材路线 AAA 正常评级，ABB 最高 B，其他混合路线长期为 C。具体阈值以评分技能 `references/scoring-rules.md` 和测试为准。
- 食材路线系数只作用于食材手／全能型的个体质量，不改物种底盘。AAA 是默认长期路线；ABB 仅限有物种依据的例外；AAB／AAC 是 Lv.30 工具人并建议止步 Lv.59。
- 树果位 Lv.50 严选要求树果数量 S；严格毕业为树果数量 S＋帮手奖励＋实际个人速度收益。
- 正式奶妈 Lv.50 要求技能概率提升 M＋帮手奖励＋一项有效增益。
- 普通／短上场工具技能位要求技能概率提升 M＋任意两项有效增益，帮手奖励不是硬性条件。
- 梦幻和达克莱伊使用幻之宝可梦全能型个体质量：把已开放副技能分别按树果、食材、技能定位归一化，再采用手动指定或自动最强定位。固定性格不参与可洗质量，未开放灵感种子栏位不按零分，食材路线系数只作用于食材分支。梦幻选择树果骤增时为 S 级，其他技能为 B 级；达克莱伊为 S 级。未知的梦幻额外糖果价值保持排除，不得暗中折算。
- 不把缎带当长期严选条件；用户认为以后最终会达到最高档。

### 3.2 队伍与生产

- 帮手奖励按每位成员叠加，并对每名成员重新计算；帮速总缩减上限 35%，不能写成一个平铺产出倍率。
- 好露营券：帮忙速度 1.2 倍、持有上限 1.2 倍、锅容量 1.5 倍。
- 活力五档实际间隔倍率为 0.45／0.52／0.58／0.66／1.00；时间轴每 10 分钟下降 1 点活力。
- 技能／全部专长可储存 2 次，树果／食材专长储存 1 次；未收取时受储存上限影响，切队可选择先收取，否则清空待发动技能。
- 满包后停止食材和技能抽取，只保留树果偷偷帮忙。
- 当前队伍页面的“纯能量”不把普通食材或资源技能强行换算成料理能量。
- 料理强化 S 是扩锅；料理成功 S 才是用户所说的“爆锅”。露营券可提供容量，但不能替代爆锅概率。
- 超幸运、怪力钳等缺少可靠分支概率时展示上下界，不伪造精确均值。
- 梦之碎片、食材、糖果、锅容量、回复和树果汁保留原单位；只有有可靠能量定义的部分才计入卡比兽能量。

### 3.3 个人资料与全站调用

- 岛屿加成输入是百分比，能量乘数为 `1 + 加成%`；它不改变树果／食材数量。
- 食谱输入是等级，不是百分比。食谱等级大于 0 就表示已做过；0 级就是未做过，不设第二个完成勾选。
- 食谱能量必须从等级查得对应加成，再叠加活动、周日与大成功倍率。
- 当前限制：个体／食谱 Lv.70、研究等级 70、岛屿加成 85%、永久锅 81、料理强化累计 200、食材袋 800、盒子 1400。
- 修改个人设置或具体宝可梦后，事件驱动的页面应立即重算评价、定位、队伍与推演；不需要用户把资料重新提交给开发者人工计算。

### 3.4 安全与产品口径

- 网站不得自动放生。培养判断先用物种梯级 × 个体梯级固定矩阵；只有基础结果为暂不培养时，闪光或限定才改判“收藏保护”，其余为“放生”建议。已有投入、盒子分类和独特路线不覆盖该判断。
- “种族强”不等于“该账号现在应培养”；“当前可用队”不等于“岛屿理论毕业队”。
- 攻略资料用于战略层，RaenonX 用于可量化生产输入，官方公告用于活动与硬规则；来源性质要写清。

- 盒子侧栏内的 2–5 个体生产对比，以及友情徽章／副技能抽取／毕业概率小工具。
- 食谱多食材筛选、未做过筛选和按个人食谱等级计算能量。
- 本周作战的库存联动、准备队／爆锅队／岛屿队时间分配、15 分钟粒度的每天上场时段和活动周完整推演。

- 治疗、额外帮忙、树果骤增、技能复制、梦魇、蹭蹭脸颊、料理类和多种资源型复杂技能的队伍效果。
- 普通岛与 EX 岛推荐；EX 的主／副树果差异与每周追加效果已经进入共享计算。
- 梦幻十项全能技能／食材变化与达克莱伊梦魇机制能随个体编辑实时进入生产、推演和个体质量；梦幻梯级随当前选定技能切换，达克莱伊的生产推演继续使用两名非恶队友的标准场景。

## 5. 仍需交接或用户裁决的事项

### P0：先保证同一套数学在各页面一致

1. **当前队伍与活动推演一致性审计**：这是下一项最有价值的工作。同一五人、同一时间、同一岛屿／露营券／收菜设置下，逐项对比普通帮忙、偷偷帮忙、树果、食材、技能触发、活力和纯能量；差异必须能解释为页面目的不同，而不是重复公式漂移。
2. **活动资料维护**：当前活动档案直接写在 `weekly-planner.js` 和 `index.html`。它不会自动日更；每次官方公告变动要同步活动时间、区域、倍率、兑换截止和第 1／2 周差异，并补测试。

### P1：已知的模型边界

- 多个体对比的 10%–90%区间使用均值／方差的正态近似，不是逐次随机蒙特卡洛；极低次数或高度离散技能时区间只是“常见波动”提示。
- 挥指需要随版本维护动态技能池，目前故意不写伪精确队伍收益。
- 超幸运的结果分支概率、怪力钳的大成功概率仍需可靠来源；现在只显示单次范围。
- 礼物等带糖果分支的技能，糖果概率或价值不明时不计算完整总价值。
- 额外帮忙已能计入队伍收益，但游戏的绝对 999 队列上限尚未形成长期跨时段状态模型。
- 本周推演是期望值：大成功发生时点、临时操作失误、额外填锅食材、活动随机树果等会造成实收差异。
- 奖励减速线来自社区研究曲线，页面必须继续写明不是官方阈值。
- OCR 未实现。用户明确重视准确率；除非建立截图模板、字段置信度与逐项人工确认，不要用低可靠 OCR 替代手动录入。
- SP 当前只保留为参考字段，不作为生产或评分真值；暂时没有复算 SP 的产品需求。

### P2：同步与维护边界

- 云端当前同步：个体、回收站、数据元信息、盒子管理、等级覆盖／历史、当前队伍、保存队伍、本周计划、个人设置和账号阶段。
- 当前没有上云：多个体对比侧栏的临时选择、当前队伍页面的部分界面／能量偏好，以及其他纯 UI 状态。这些跨设备恢复前必须先决定它们是个人资料还是临时操作。
- `data/raenonx-species.json` 不会自动刷新。游戏新增或调整宝可梦后，先运行同步器自检，再同步、重建目录和生产快照。
- 逻辑测试覆盖较全，但没有浏览器端端到端测试；弹窗、抽屉、横向滚动、键盘和手机安全区仍需人工验收。

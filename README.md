# Pokemon Sleep 助手

一个以个人宝可梦盒子为基础的静态 Pokemon Sleep 辅助网站，可直接离线使用，也可通过 GitHub Pages 发布。

## 功能

- **盒子**：查看 97 只宝可梦的树果／食材／技能／全能定位、闪光状态、食材、技能和性格；副技能按解锁等级竖排，可直接按综合评分排序，悬停分数可查看最终形态、Lv.70 副技能、性格、食材组合与成长曲线构成。
- **正作式盒子管理**：提供 8 个可重命名盒子、卡片式多选和批量移动；每只宝可梦可独立设为“参与实战”或“仅收藏”。仅收藏个体仍保留在盒子和评分中，但不会进入岛屿自动队伍、活动补位、食材推荐或当前队伍的新选择。
- **实际副技能升级**：逐栏记录游戏中已经发生的副技能种子升级；只允许已解锁栏位，并校验 S→M、持有上限 S→M→L、上位技能占用及重复技能冲突。实际状态会更新当前间隔、持有上限和产出，Lv.70 潜力评分仍按合法满配上限独立计算。
- **等级快速更新**：可按全部、当前队伍、已保存队伍、重点培养或最近修改批量更新当前等级，也可从盒子单行及当前队伍成员直接调整；支持 `−1`、`+1`、`+5`、批量保存和撤销最近一批修改。
- **当前队伍**：从盒子中选择五只具体个体，汇总当前等级已解锁食材的单次收菜与 24 小时期望，并按持有上限估算建议收菜间隔；可在本机保存最多 10 支完整队伍，一键切换成员、活力模型与好露营券设置。
- **岛屿推荐**：查看全部普通岛屿与 EX 岛屿的推荐排序及五人队伍；自动比较无特殊宝可梦主队与特殊宝可梦备选，并可为萌绿之岛及两个 EX 选择本周树果后动态重算。
- **料理食谱**：查询料理基础能量、能量系数、锅容量和所需食材，并从当前盒子推荐食材宝可梦。
- **食材图标**：盒子、岛屿说明、料理、活动计划和当前队伍中的食材名称统一显示本地透明图标；19 种图标均随网站一起保存，可离线使用。
- **活动资讯**：查看近期活动倒计时、活动效果、推荐队伍和活动前中后计划。
- **特殊宝可梦规则**：通常每队最多一只特殊宝可梦；拉帝亚斯与拉帝欧斯可以作为官方例外同时编队。

## 本地使用

直接双击 `index.html` 即可。网站不需要安装依赖、运行构建命令或连接数据库。

旧入口 `Pokemon_Sleep_97只宝可梦整理.html` 会自动转到 `index.html`，原有书签仍可继续使用。

## 发布到 GitHub Pages

1. 在 GitHub 创建一个仓库，并把本项目推送到 `main` 分支。
2. 打开仓库的 **Settings → Pages**。
3. 在 **Build and deployment → Source** 中选择 **GitHub Actions**。
4. 推送到 `main` 后，`.github/workflows/pages.yml` 会自动部署网站。

部署成功后，可以在工作流的 `deploy` 任务或仓库 Pages 设置中看到网站地址。

## 数据说明

- 盒子个体数据来自个人游戏截图和手动校对。
- 攻略、食谱和排序综合参考 Pokemon Sleep 官方公告、新版日文 Game8 与 RaenonX；种族量化以 RaenonX 图鉴和生产率资料为主要计算输入，Game8 用于定性复核，并按当前 Lv.70 上限评价。
- `data/raenonx-species.json` 是可复现的数据快照，当前含 247 条图鉴记录以及帮忙间隔、持有上限、树果数量、食材栏、主技能、食材概率和技能概率等字段。概率属于 RaenonX 研究估算，并非游戏官方公开值；主技能会逐只与当前日文主技能别列表交叉校验，现有 50 条 RaenonX 原始编号错位均连同来源保留在 JSON 内。
- 当前队伍页以盒子中记录的当前等级、当前间隔和持有上限为起点，加入已解锁的食材概率副技能、性格、帮手奖励、树果数量 S、活力档位及好露营券后估算。建议时间优先避免食材手／技能手满仓，并在预计满仓前保留约 15% 空间，最长按用户习惯给到 4 小时；树果手满仓后的偷偷吃树果仍保留，但食材与主技能抽选会停止。页面的固定食材数量不含随机食材类主技能，因此属于规划期望值而非实收保证。
- 当前队伍及最多 10 支收藏队伍使用浏览器本机存储，不上传服务器；重复保存同一成员顺序会更新原收藏而不会额外占用名额。食材图标来自 Game8 食材能量页面的 2026-08-30 快照，逐项来源记录在 `assets/ingredients/SOURCES.md`。
- 盒子分类、盒子名称、实战资格与实际副技能升级使用浏览器本机存储，不改写原始 97 只快照。首次使用时，原建议为“闪光收藏”的个体会进入闪光收藏盒并退出实战；标为“闪光且可用”的个体仍保持实战资格，之后均可手动修改。
- 实际副技能升级与潜力评分相互独立：前者使用 `effectiveSubs` 参与当前等级的生产与收菜计算，后者继续读取原始五栏并按副技能种子最高合法潜力评分。网站记录的“回退”只用于修正本地记录，不代表游戏内可以降级。
- 等级修改作为独立覆盖记录保存在浏览器，不会改写原始 97 只盒子快照。更新等级时，以原始个体间隔和持有为基准，按每级 0.2% 的帮忙间隔变化、新解锁的帮忙速度 S／M 与持有上限 S／M／L 重算；跨过 Lv.30／60 食材槽或副技能节点后，当前队伍与食材推荐会立即采用新状态。最终综合评分仍表示 Lv.70 潜力，不随当前等级改变。
- Lv.80 副技能以 10% 权重保留长期潜力；当前可用的 Lv.10／25／50／70 栏位合计占 90%。
- 当前综合100分采用用户确认的“最终形态种族分75%＋个体分25%”。个体分由副技能合法满分百分分70%＋有正负号的性格理论百分分30%组成，食材手再乘AAA 1.00、ABB 0.85、ABA 0.80、AAB／AAC 0.70、ABC 0.50的组合系数；中性性格为0。五个副技能栏位按25%／25%／25%／15%／10%，计入合法种子升级、S＋M共存和乘算交互。食材手种族分采用“生产80%＋最终形态持有10%＋主技能协同10%”；树果手采用“Lv.70树果生产90%＋主技能协同10%”。技能手种族分由53只最终形态的个人队伍收益校准，并保留50%跨定位补偿及用户人工物种校准。当前盒子95只已取得完整综合分；梦幻和达克莱伊因全能型公式未定显示“待定”。少数尚未独立建模的副技能使用明确标注的暂定桥梁，悬停分数可查看全部构成。
- 副技能先按定位取得原始适配收益，再按 Lv.10／25／50／70／80 栏位乘以 25%／25%／25%／15%／10%，最后除以同定位最佳合法五栏组合的原始上限，转换为0–100分。当前上限为树果手66.7、食材手70.0、技能手70.0；因此100分表示游戏规则下真正可出现的最佳组合，而不是五个重复的100分技能。副技能占个体分70%，折算到最终综合分最多17.5分，性格最多7.5分（食材手个体区块再乘食材组合系数）。Lv.80占副技能原始值的10%，表示尚未开放的长期潜力。
- 可升级副技能按副技能种子满配后“实际可达到”的最高组合计分：单独的帮忙速度 S 按 M 潜力计；同时拥有 S＋M 时则保留 S 与 M 两个栏位分别计分，因为效果可以叠加，但游戏不允许把 S 再升成第二个 M。持有上限 S／M／L 同样按不产生重复技能的最高可达组合换算。
- 性格评分以无补正为 0，正收益加分、负收益扣分；食材手已有完整25种核心表，树果手按最终形态基础食材概率分别生成25种表。规则与计算脚本位于 `skills/pokemon-sleep-scoring`。
- 活动内容会随官方公告变化，当前页面中的活动资料属于标注日期的数据快照。
- 本项目是个人辅助工具，与 The Pokémon Company、SELECT BUTTON inc. 或 Pokémon Sleep 官方无隶属关系。

## 更新 RaenonX 数据快照

需要联网和 Node.js。先运行全图鉴主技能校验及沙奈朵生产率样本自检，再同步全图鉴：

```powershell
node .\scripts\sync-raenonx-species.mjs --self-test
node .\scripts\sync-raenonx-species.mjs
```

同步器默认并发数为 4；可用 `--concurrency=1` 至 `--concurrency=8` 调整。若有详情页抓取失败，或任一宝可梦无法与当前主技能资料唯一匹配，同步会失败，不能把残缺快照当作完整评分输入。
